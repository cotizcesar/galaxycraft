# 2026-11-08 — command card, ready rooms, special rules and cheats

This round closed the command-card dispatch gap found while auditing the
playable client: the simulation already implemented most abilities, but the
button action match fell through to `not implemented yet` for many of them.

## Evidence source

The shipped `x86/StarCraft.exe` (SHA-256
`32dbbdd001dd381cb1b3a719b7ad1fc918a9d4bc99661c675e00254efecca827`) is
packed.  A read-only runtime capture of the 32-bit client under Wine
(`.text` entropy 6.895 after unpacking) was disassembled and, for 56 action
routines, decompiled with Ghidra 12.1.2.  The per-address evidence is in
[`command-card-re.md`](command-card-re.md).  No retail bytes are stored in
the repository.

## Command card

- `buttons::Act` now classifies every action address that appears in the
  shipped 250-set button table.  A test fails if a future fixture introduces
  an unclassified button.
- New actions: Load, Unload, Nuclear Strike, Heal, Infest, Spawn Larva,
  Shield Battery recharge, build Interceptor/Scarab, Archon Warp, Dark
  Archon Meld, Cloak/Decloak, Morph Unit/Building, and the race-specific
  cancel buttons.
- `Morph Unit` now morphs larvae, Hydralisks and Mutalisks (previously it
  called the building trainer, so a Zerg player could not use the card at
  all).  `Morph Building` upgrades Hatcheries/Lairs/Spires/colonies.
- Carrier/Reaver move/stop/attack variants share the generic orders, so
  those units are commandable again.
- Load/Unload work for Dropships, Shuttles, Overlords and Bunkers (the
  selected-unit filter now includes Bunkers).
- Every direct ability is logged: replay/save version 4 adds tags for unit
  morphs, cloak, nuke, shield battery, hangar units, larva spawn, add-on and
  morph cancels and cheats.  Version 2/3 files still decode.

## Special game modes

- `Greed`: the first player to gather **10,000 minerals and 10,000 gas**
  wins (the shipped `Greed10000.trg` requires both accumulate conditions;
  see [`game-types-re.md`](game-types-re.md)).
- `Slaughter`: after 30 minutes the player with the most kills wins.
- `Sudden Death`: destroying a Command Center, Nexus, Hatchery, Lair or Hive
  defeats its owner.
- **Capture the Flag**: each player gets a flag beacon near its town hall;
  flags appear after three game minutes.  Workers pick up enemy flags,
  dropped flags return after 30 seconds, and carrying an enemy flag onto the
  carrier's own beacon eliminates the flag owner.  The beacon can be moved
  once during the first ten minutes (`PlaceBeacon` card button).  Flags and
  beacons are drawn in both the SD and HD views.
- `Team Capture the Flag` uses the same rules with lobby teams.

- Remastered CEF chrome is now read from `locales/<locale>/assets/rez/gluall.json`:

  display-mode/language lists, the Options row tooltips, the Hotkeys panel
  headings/hints/buttons and the Collections sections/EQUIP button.  Missing
  locale keys fall back to English.
- The build footer and text-field language tag now show the loaded locale

## Controller

- New `engine-rust/src/bin/sc_view/gamepad.rs`, backed by `gilrs` (evdev on
  Linux, XInput on Windows, IOKit on macOS).  `SC_GAMEPAD=0` disables it.
- Left stick drives the virtual cursor; A selects/clicks, B smart-commands,
  X attack, Y selection cycle, D-pad/right stick pan the camera, LB/RB are
  Shift/Ctrl, Start is F10, Select is objectives, L3 centres, R3 cycles
  selection.  Menus map A/B/Start/Select/arrows to Enter/Escape and the
  direction keys.  The raw mapping is unit-tested without a device.
- `scripts/virtual_gamepad_test.py` creates a temporary uinput Xbox-style
  pad and injects stick/button events; `sc_view --gamepad-probe 4` reports
  the real `gilrs` frames.  The run passes active frames, menu Enter, the
  attack `A` edge, D-pad Left, a held South click and right-stick pan.
  This exercises the kernel evdev -> gilrs -> mapping path; a physical
  controller is still needed for the final hardware check (none is
  connected to this machine).

- `scripts/lan_two_machines.sh host` / `join HOST` runs the headless lockstep
  client over a real network.  A loopback pair was run here and both peers
  finished with the same state hash (`ffbad93e128c72f3` at turn 200); a

- `tests/retail.rs::later_campaign_missions_open_with_their_authored_cues`

  within 30 s.  This is the strongest later-campaign check possible without
  retail footage.

## Options now reach the client

- `Unit Speech` gates selection/ready voices and `Unit Acknowledgments` gates
  the command replies.
- `Key Scroll Speed` and `Mouse Scroll Speed` scale the keyboard camera and
  mouse-wheel steps around the retail default.
- `HD Graphics` switches the world between the HD and SD renderers at high
  window scales; `Real-Time Lighting` gates the shipped point-light pass.
- `Game Timer` and `Display APM` draw the shipped `console_time` /
  `console_apm` plates at the top right, with the mission clock and the
  command count per minute (`--hud-stats` forces both for captures).
- The APM alert threshold is an editable, persisted field (default 60).
  After the first minute, a below-threshold APM turns red with `Color Text`
  and plays the UI warning cue with `Play Sound`.
- `Enable FPS Cap` drives the window polling rate over the retail 100-300
  range; with the cap off, `Enable Vertical Sync` falls back to 60 Hz and
  both off leaves the loop uncapped.  minifb has no native VSync switch.
- `Shadow Stacking` turns the HD below-unit shadow layers on/off.
- `Environment Effects` draws a deterministic per-era particle field from
  the shipped `hd2/effect/particle.dds` (ash, snow, dust, spores, smoke and
  platform motes; positions derive from the mission tick, so captures and
  replays are identical).
- `Smooth Unit Turning` interpolates the rendered facing over the 256-step
  circle (24 steps per game tick) while the simulation keeps its exact byte
  facing; both the SD GRP path and the HD sprite path use it.
- `Pillarbox` restores the original 4:3 playfield: game screens draw into a
  centred 4:3 content box with black side bars (`--pillarbox` for captures),
  while menus, briefings and movies stay 16:9.
- `Enable Color Cycling` rotates the SD terrain palette ranges every three
  game ticks (125 ms): badlands/jungle 1-6, 7-13 and 248-254; ashworld
  1-4, 5-8 and 9-13; desert/ice/twilight 1-13 and 248-254;
  platform/installation do not cycle. The option is live and restores the
  base palette when cleared.  HD megatiles are pre-coloured DDS surfaces,
  so the HD path detects the same water/lava megatiles from their SD palette
  indices and applies a small luminance wave to their blue texels at the
  same 8-rotations/second rate; cliffs and shore art keep their colour.
- `Mature Language Filter` masks whole words in trigger text, cinematic
  subtitles and LAN chat. Retail filters Battle.net chat server-side and
  ships no local word list, so the local list is an explicit conservative
  inference.
- `SD Graphics Filter` selects nearest-neighbour at its sharpest stop and
  the measured bilinear upscale for the filtered stops.
- `Hardware Cursor` shows the system pointer and suppresses the drawn
  cursor; the software cursor is restored when the option is cleared.
- Network tab `Prefer Port 6112` binds and announces 6112 instead of the
  client's historical 7777.  `Latency` maps Low/High/Extra High to 4/6/8
  lockstep turns per network turn, carried in the host's Setup message.
- Game tab `Mini-Map Position` now has both retail states: `Left Corner`
  keeps the classic left anchor, while `Standard` shifts the left console
  plate and the minimap towards the centre of a widescreen playfield by the
  spare width; at 4:3 the two layouts coincide (`--minimap-standard`).
- Speed tab `Mouse Sensitivity` (0.5 = retail default 1.0) and
  `Use Mouse Scaling` now drive a virtual software pointer from raw deltas,
  so the drawn cursor and every click agree.  Hardware Cursor falls back to
  the software pointer when movement is scaled, as its retail tooltip says.
- `Show Bonus Skins` loads the shipped PreSale skin containers
  (`anim/presale/main_NNN.anim`, `hd2/anim/presale/skin.json`) for Scourge,
  Command Center, Infested Command Center, Hatchery, Lair, Hive and Nexus;
  clearing it returns to `anim/main_NNN.anim` (`--no-bonus-skins`).
- `Friends presence text notifications` uses the shipped
  `bnet_friendFollow_online/offline` strings for the only presence source
  this client has, LAN peer drop/rejoin events.

## Campaign AI opcodes

- `set_attacks` now keeps the melee `target_expansion` launch budget and
  `target_expansion` spends one credit per launch; campaign scripts keep
  their one-shot expansion attack.
- `if_dif` compares the active-thread difficulty (1 active, 0 inactive).
- `move_dt` sends every Dark Templar to the trigger location.
- `fake_nuke` clears the AI's pending nuke state.
- Trigger AI locations are converted from map pixels to whole tiles before
  they reach `Order::Move`, patrol, nuke, recall and Disruption Web orders
  (previously every location-targeted AI order used pixel values as tiles).
- Added the retail AI region-state graph (`World::ai_region_states`, one
  0-9 state per pathfinding region and player):
  `guard_all` marks every region containing the player's units as a town
  (5), `implode` marks low-connectivity state 0-3 regions as defend (4),
  `value_area` marks its trigger region as a town unless an enemy is inside,
  and `help_iftrouble` copies the player's non-zero regions to allied AIs as
  state 4.
- `quick_attack` shortens the next attack deadline to five seconds;
  `attack_do`/`target_expansion` mark the target region as attacking and set
  the retail 120/180-second (or one-second expansion) deadline;
  `wait_finishattack` blocks until the deadline and then clears state
  1/2/8/9; `attack_clear` clears them immediately.
- A shipped `TB8B` test runs the real `guard_all` script on a town and
  observes state 5, and synthetic tests cover implode, value_area,
  help_iftrouble, quick_attack and wait_finishattack.

## Campaign AI economy

## 32-bit runtime image

- The 32-bit client now runs with the retail Battle.net prefix and the
  retail launcher arguments:

  ```text
  WINEPREFIX=$HOME/.wine wine \
    "Z:\...\StarCraft\x86\StarCraft.exe" -launch -uid s1
  ```

- WineDbg attached to the Windows PID (`tasklist`: `StarCraft.exe 696`) and
  dumped the live module image at `0x400000..0x14ce000`:
  **17,620,992 bytes**, SHA-256
  `7dfc23657e770773d6e4d6de52efc241b87ebde5acd06e4892e288caa6307a6e`.
- The raw memory image's section pointers were rewritten to their in-memory
  offsets; the resulting analysable PE is preserved outside the repository at
  `~/.cache/galaxycraft/sc32_runtime_pe.bin` (SHA-256
  `70e6779de6b496bd663e10510e159210b48f2c1b0f41049a3c3f6586e5d17738`).
- Checks: bytes at `0x52ce00` decode as the expected `mov eax, ds:0xf356e8`
  function prologue, and `0x74d4c0` is the recovered button-action region,
  proving this is the unpacked runtime rather than the packed on-disk stub.

## Function-coverage inventory

- REA/Ghidra 12.1.2 analysis of the extracted 1.23.10 runtime image
  (SHA-256 `34ed2783e0370343f74cfa928eab37e957c5e63a87bd2a4414910e0e0b46531c`)
  reports **39,953 procedures**, **18,879 defined strings**, and a 9.63 MB
  `.text` segment.  The analysis profile disabled Function ID, Decompiler
  Parameter ID, Decompiler Switch Analysis, Embedded Media and Create Address
  Tables.
- A later capped 600-second pass produced a local inventory of **9,038
  functions** (213 thunks); that partial result is superseded.
- The reproducible full pass on the current image
  (`sc32_runtime_pe.bin`, SHA-256 `70e6779d...`) uses Ghidra 12.1.2 with the
  same five analyzers disabled and finds **56,128 functions, 270 of them
  thunks**.  **56,127** lie in `.text` (`0x469607..0xd2f390`); one is a data
  false positive.  The count is larger than REA's 39,953 “procedures” because
  it includes every discovered entry, thunk and CRT/unwind helper; the exact
  filter REA applied to that number is not recorded (INFERENCE).
- `scripts/function_coverage.py` now uses the `0x79fa0000 -> 0x400000` delta
  (`0x79ba0000`).  Of **564 retail addresses cited by the reconstruction's
  Rust, tests and documents**, **411 fall inside a discovered function body**
  (408 unique functions); the old research tree gives 413 of 537.  The
  remaining citations are data addresses, inlined code or candidates for the
  retry pass.
- The full pseudocode pass wrote **55,501 of 56,128 functions (98.88%)** to
  `~/.cache/galaxycraft/decomp_full` (`scripts/decompile_parallel.sh`); one
  partial warning body recovered in the retry pass brings the corpus to
  **55,502 bodies**.  All **627** original failures were attempted one at a
  time: 595 small functions all failed (bad control flow), 32 large ones gave
  1 warning, 25 failures and 6 `halt_baddata` bodies.  The 626 remaining
  failures are listed in `~/.cache/galaxycraft/decomp_failures_final.tsv`;
  their attempt status is in `decomp_attempts_final.tsv`; Hopper and Rizin/rz-ghidra
  were also tried on samples and produced no pseudocode.  The Ghidra project
  lives at `~/galaxycraft-work/ghidra_full` because Ghidra rejects hidden
  project path elements such as `.cache`.
- The highest-impact uncovered option key found this way was the retail
  `ShowFPS` setting.  It is now persisted and draws a small `FPS <n>` overlay
  (`--show-fps` for captures); it is not shown in the four Options tabs because
  the retail setting is hidden debug chrome.
- The inventory is deliberately not committed: it is derived retail metadata,
  not shipped source.  Only aggregate counts and the methodology are recorded.
