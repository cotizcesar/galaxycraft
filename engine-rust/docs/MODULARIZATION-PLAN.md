# Modularization plan

Goal: no agent has to read a huge file.  Every phase is a pull request that
only moves code, with no logic changes.  Planned 2026-11-12 in a separate
planning session; **done 2026-11-12** (see "Result" at the end).  Run it between waves and with no
feature branch open: phase 5 collides with any branch that touches `sim.rs`
(for example `vehicles/retail-polish`).

## Diagnosis (measured 2026-11-12)

| file | lines | shape |
|---|---|---|
| `src/runtime.rs` | 99 595 | 552 blocks `// Merged from src/waveNN/agentNN.rs`, each with its tests |
| `src/client.rs` | 75 007 | 150 merged blocks (the whole file is wave output) |
| `src/sim.rs` | 38 483 | hand-written up to about line 14 750 (one `impl World` of ~12 800 lines and 447 methods, tests after it), then 56 merged blocks |
| `src/bin/sc_view.rs` | 30 596 | two `impl App` (12 600 and 7 100 lines) and a `main` of 1 966; `src/bin/sc_view/gamepad.rs` and `mp.rs` already exist via `#[path]` |
| `src/ai_recovered.rs` | 13 331 | 11 merged blocks |

Only 7 calls to `wNNaNN_` functions come from outside their own file, so
splitting the wave files is mechanical.  `client.rs` has 10 `impl World`
blocks and `runtime.rs` 5 (a layering inversion).

## Invariants every phase keeps

- `cargo test --lib` and `cargo test` pass with the same counts as before
  the move.
- Ledger `translated` unchanged.
- `cargo fmt --check` and `clippy -D warnings` clean; determinism and replay
  tests green.

## Phases

1. **Tool and baseline.**  `scripts/split_merged.py` cuts on the
   `// Merged from` markers.
2. **Pilot: `runtime.rs` -> `src/runtime/`.**  One file per block,
   `src/runtime/w31/a07.rs` (the `w31a07_` prefix gives the path).
   `runtime/mod.rs` keeps the `#![allow(clippy::...)]` lines and re-exports
   with `pub use` so no public path changes.  Risk: blocks that use private
   helpers of another block; raise those to `pub(super)` as the compiler
   asks.
3. **Pipeline, in the same PR as the pilot.**  `merge_wave.py` stops
   appending and writes `src/<module>/wNN/aNN.rs`; `triage_corpus.py` votes
   the module by directory instead of by file name (the GAMEPLAY / CLIENT
   sets and `module_of`); `decomp_ledger.py` needs no change (it already
   uses `rglob`).
4. **Repeat** for `client.rs`, `ai_recovered.rs` and the tail of `sim.rs`
   (to `src/sim/translated/`).  Move the 15 `impl World` blocks of
   `client.rs` / `runtime.rs` into `sim/`.
5. **`sim.rs` -> `src/sim/`.**  One `impl World` per subsystem in child
   modules (children of `sim` see `World`'s private fields, so no
   visibility or API change).  `mod.rs` keeps the types and `World`;
   tentative files: `spawn.rs`, `step.rs`, `order_exec.rs`, `movement.rs`,
   `attack.rs`, `spells.rs`, `production.rs`, `transport.rs`, `nuke.rs`,
   `queries.rs`; tests to `sim/tests/`.  Splitting the largest methods
   comes later, in separate PRs.
6. **`sc_view.rs` -> `src/bin/sc_view/main.rs`.**  Split `impl App` by
   screen (menu, match, briefing, options, drawing, input); afterwards a
   State pattern with an `enum Screen` and `update` / `draw` per screen.
7. **Guard rails.**  A CI check with a line limit per file (proposal: 1 500
   for hand-written files, with an exception list that may only shrink);
   `docs/MODULES.md` generated by a script; update the token rules in
   `AGENTS.md`; list the move commits in `.git-blame-ignore-revs`.

Optional at the end: split into crates (simulation without I/O, client,
tools).

## Notes

- The exact cuts of `World` and `App` are tentative: they come from the
  names of the largest methods, not from a call analysis.  Do that analysis
  when phases 5 and 6 start.
- `AGENTS.md` still quotes older line counts; update it in phase 7.

## Result (2026-11-12)

| phase | done |
|---|---|
| 1 | `scripts/split_merged.py` |
| 2-4 | `runtime.rs`, `client.rs`, `ai_recovered.rs` and the translated tail of `sim.rs` split one file per wave block; `mod.rs` re-exports, no public path changed |
| 3 | `merge_wave.py` writes `src/<module>/wNN/aNN.rs`; `triage_corpus.py` votes the module by directory (same `triage.tsv`) |
| 5 | `impl World` split into 15 subsystem files (`scripts/split_impl.py`, plan `scripts/sim_split.json`); tests in `sim/tests.rs` |
| 6 | the two `impl App` blocks split into 19 per-screen files under `bin/sc_view/` (plan `scripts/sc_view_split.json`) |
| 7 | `scripts/check_file_sizes.py` + `docs/large-files.txt` (CI: `.github/workflows/checks.yml`), `docs/MODULES.md` generated, `AGENTS.md` updated, `.git-blame-ignore-revs` |

Not done: the `enum Screen` state pattern for `App`, splitting the largest
single methods (`handle_menu_input`, `draw_options`, `draw_hotkeys`,
`draw_lobby`, `apply_spell`), moving the `impl World` blocks of the wave
files into `sim/`, and crates.

Proof that nothing changed:

- `cargo test`: 5167 passing before and after (lib 4826); clippy and fmt
  clean.
- Ledger: 5736 translated, the same set of addresses.
- The same scripted game (melee map, Siege Tank, Goliath, Science Vessel,
  Dropship, Marine against Zerglings and an Ultralisk, 260 ticks) run with
  the binary built from `main` and from the split: unit dumps and the
  per-step state log are byte-identical in HD and SD; screenshots differ
  only in the talking portrait's mouth, which follows the wall clock and
  differs between two runs of the same `main` binary too.
