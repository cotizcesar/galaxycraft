# Wave agent instructions (GalaxyCraft decompilation translation)

This is the prompt template for a ten-agent translation wave.  Replace
`NN` with the agent number and `W` with the wave number.  The assignment
file is generated by `scripts/prepare_wave.py`.

## Context

GalaxyCraft is a Rust reconstruction of the StarCraft 1.23.10 engine.
The decompiled corpus is read-only evidence:

```
~/.cache/galaxycraft/decomp_full/          # one .c file per function
~/.cache/galaxycraft/functions_full.tsv    # address, name, size, thunk
engine-rust/docs/decomp-ledger.tsv         # status per function
```

Work in the repository root `/home/cotizcesar/Documents/galaxycraft`.
Read `engine-rust/docs/TRANSLATION-PIPELINE.md` for the current stop point
and the exact commands.

## Task

Translate the recoverable functions in your assigned address window into
idiomatic, safe Rust.  Write exactly one file:

```
engine-rust/src/waveW/agentNN.rs
```

The assignment `/tmp/opencode/waveW/agentNN.md` lists every candidate with
its pseudocode path and the known-unrecoverable rows.  Do not edit
`lib.rs`, `Cargo.toml`, a natural module, the ledger, or another agent's
file.  The isolated harness `engine-rust/tests/waveW_agentNN.rs` compiles
your file as an integration-test module:

```rust
#[path = "../src/waveW/agentNN.rs"]
mod batch;
```

Use `galaxycraft::...` paths; `crate::` in the harness would refer to the
test crate.  Prefer fully qualified calls over top-level `use` statements
so the batch can be pasted into a library module.

## Rules

1. Read the pseudocode of every candidate before translating it.
2. Translate into pure free functions over borrowed data, slices, indices
   and caller-supplied closures.  Never invent behaviour the pseudocode
   does not show.
3. Every implemented routine must carry a doc comment with its exact
   address:

   ```rust
   /// `0x00670abc`: returns the slot whose cached id equals `wanted`, or
   /// `None`.  The record stride is `0x34` (patch 1.23.10).
   pub fn wWaNN_find_slot(rows: &[u8], wanted: u16) -> Option<usize> { ... }
   ```

   The ledger credits an address only when it sees the literal `0x...`
   text.  Cite every implemented address, and no other address.
4. **Ledger hygiene:** skipped addresses must be written as
   `FUN_00670abc` or bare hex (`670abc`), never with a `0x` prefix.
5. Prefix every top-level item with `wWaNN_`.
6. Put tests in the same file:

   ```rust
   #[cfg(test)]
   mod tests_waveW_agentNN { use super::*; ... }
   ```

   Add at least one focused test per routine, or one grouped test for tiny
   predicates.  Cover boundary values and recovered constants.
7. Do not wire translations into `World`, `SimUnit`, the renderer or the
   client.  They are auditable reference helpers.  Do not add save/replay
   state.
8. Skip, with a reason, any candidate whose pseudocode is:
   - `DECOMPILE_FAILED`, `halt_baddata`, or dominated by
     `WARNING: Control flow encountered bad instruction data`;
   - an empty/one-byte `ret`, a bare `unaff_*`/`in_*` fragment, or a
     mid-function block with no recoverable arguments;
   - a jump-table body whose branches Ghidra could not recover;
   - dependent on an opaque global whose layout is not visible.
   Prefer ten real translations over thirty fabricated ones.
9. Target 15–25 translated functions when the window has enough material.
10. Do not copy retail assets or large pseudocode bodies into the repo.

## Verification

From `engine-rust/`:

```bash
rustfmt --edition 2024 src/waveW/agentNN.rs
cargo test --test waveW_agentNN
```

The harness compiles the library plus only your batch.  If a compile error
points at another `waveW/agent*.rs`, ignore it and retry later; never edit
that file.

## Final report

Return:

1. `translated:` exact addresses implemented.
2. `skipped:` address + one-line reason.
3. `tests:` final command and pass/fail counts.
4. `notes:` recovered layouts or uncertainty the integrator must know.

Do not claim an address unless its function exists in your file and its
test passes.
