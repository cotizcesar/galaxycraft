# Command-card action evidence (1.23.10.13515)

The command card is data in `x86/StarCraft.exe` (button-set array, RVA
`0xb2ddf8`), but every button's `act` field names an action routine.  This
note records how each previously-unhandled action was identified so the
client no longer falls back to `not implemented yet`.

## Target and runtime image

- Shipped artifact: `x86/StarCraft.exe`, SHA-256
  `32dbbdd001dd381cb1b3a719b7ad1fc918a9d4bc99661c675e00254efecca827`.
  Its `.text` is packed (entropy 7.9997), so static disassembly of the file
  does not show the game code.
- Read-only runtime capture: launched the 32-bit client under Wine on a
  private Xvfb display and read `/proc/<pid>/mem` with
  `research/tools/capture_memory.py` (no debugger, no writes).  The rebuilt
  PE has SHA-256
  `46f6244585af0f92e6393630c0173fda1b5c7a32361410c9dca0645e83b6e027`
  and its `.text` entropy is 6.895 (decrypted).
- Disassembly below uses that image at its loaded base (`0x400000`).

## Action routines

Each routine is a small wrapper around the command poster/cursor helper
`0x79cca0` (three-byte command arguments, then a card refresh) or around a
typed ability helper.

| Address | Button | Evidence |
|---|---|---|
| `0x74d4c0` | Move | `push 6 / push 6 / push 0x31; call 0x79cca0` — row 6 is Move |
| `0x74d4d0` | Nuclear Strike | `push 0x7e` three times — row 126 is Nuke Unit |
| `0x74d630` | Shield Battery recharge | `push 0x43` three times — row 67 is Shield Battery |
| `0x74d410` | Heal | `push 0xb1` three times — row 177 is Medic Hold Position |
| `0x74d2c0` | Carrier attack | `push 0x36 / 0xe / 0x35` — rows 54/14/53 are the Carrier attack rows |
| `0x74d2d0` | Carrier move | `push 0x33 / 0x33 / 0x31` — rows 51/49 are Carrier move/stop |
| `0x74d2e0` | Carrier stop | jumps to `0x72e670`, which posts command `0x1b` |
| `0x74db90` | Carrier/Reaver stop variant | jumps to `0x72e690`, command `0x1c` |
| `0x74d3b0` | Load | checks `0x5b5810`, then `FUN_0079cca0(0x5e,6,6)` or `(0x5f,0x17,0x17)` — the transport/Bunker load commands |
| `0x74dba0` | Unload | checks `0x5b5810`; `FUN_0079cca0(0x70,0x70,0x70)` or the typed unload helper |
| `0x74d680` | Spawn Larva | large handler (checks the selected Hatchery/Lair/Hive, creates a larva through `0x7a8be0`) |
| `0x74d4e0` | Infest | calls `0x751a30` with command `0x2e` and the selected unit |
| `0x74d850` | Stop / Archon Warp / Dark Archon Meld | wrapper calls `0x72cd80(arg)`, a generic command poster; the button's `act_var` is tech 23 (Archon Warp) or 28 (Dark Archon Meld), 0 for Stop |
| `0x74d870` | Archon Warp variant | `jmp 0x72e6b0`, command `0x2a` |
| `0x74d880` | Dark Archon Meld | `jmp 0x72e6d0`, command `0x5a` |
| `0x74d290` | Cancel (Zerg building) | `jmp 0x72dd80`, command `0x31` |
| `0x74d2a0` | Cancel (Terran building) | `jmp 0x72e650`, command `0x33` |
| `0x74d260` | Build Interceptor / Scarab | `jmp 0x72bb20`; decompiles to `FUN_0073a250(..., 0x27)` (the hangar build command) |
| `0x74d5a0` | Place Beacon | reads the selected unit, posts command `0x9b` |
| `0x75c2c0`, `0x75c370`, `0x75c420` | ATS/ATA laser battery map units | separate test-unit command posters; no player rule in the reconstruction |

The action addresses are also visible in the shipped button table
(`fixtures/button_sets.in`, generated by `sc_assets fixtures`).  The
classification is exercised by
`buttons::tests::every_shipped_button_action_is_classified`.

## Behaviour selected for the reconstruction

The simulation already contains the rules-level primitives these buttons
need (`morph`, `morph_unit`, `morph_building`, `set_cloak`, `spawn_larva`,
`launch_nuke`, `shield_battery`, `build_hangar_unit`, `cast(ArchonWarp |
DarkArchonMeld | Healing | Infestation)`, `Order::EnterTransport`,
`Order::Unload`, `cancel_addon`, `cancel_morph`).  The client now dispatches
to those primitives, and every direct ability has a command-log tag so saves,
replays and LAN lockstep stay deterministic.

## Ghidra decompilation

A headless Ghidra 12.1.2 pass over the runtime capture completed
(`analyzeHeadless`, `DecompileAt.java`) and wrote the 56 action routines to
`decomp/`.  The small wrappers above decompile exactly as the disassembly
shows; `FUN_0074d680` (Spawn Larva) is one of the functions Ghidra reports as
body-repair damaged, so its behaviour is taken from the live disassembly and
the button/tooltip data.

## Limitations

- Ghidra auto-analysis of the full 17.6 MB runtime image is slow; the action
  wrappers above were read with `objdump` and then decompiled from the
  verified runtime capture.
- `0x74d850` is shared by Stop and both archon merges; the dispatch uses the
  button's `act_var` (0 = stop, 23 = Archon Warp, 28 = Dark Archon Meld).
- The laser-battery and flag-beacon buttons remain `Special`/`PlaceBeacon`
  no-ops: they are map-test units, not part of the standard tech tree.
